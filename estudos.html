O que a prova costuma cobrar

A prova prática segue quase sempre o mesmo roteiro: você recebe um enunciado com um problema (estoque, biblioteca, oficina, escola) e precisa entregar:

  1. O banco de dados: o script SQL criando as tabelas com chave primária e estrangeira, e alguns dados de exemplo. Às vezes pedem também o desenho do DER.
  2. Tela de login com validação (campo vazio, usuário errado).
  3. Tela principal que mostra os dados cadastrados, com busca e opção de sair.
  4. Tela de cadastro com validação dos campos, para incluir e editar registros.
Confirme com seu professor. O formato exato muda de escola para escola e de ano para ano (linguagem permitida, se o site precisa estar ligado ao banco de verdade, tempo de prova). O projeto do Dia 5 funciona só com HTML, CSS e JS e tem um anexo mostrando como ligar no MySQL se for exigido.

O que instalar antes de começar

  • VS Code com a extensão Live Server (botão direito no HTML, "Open with Live Server").
  • Um navegador (Chrome ou Edge). Aperte F12 para abrir o console e ver erros do JavaScript.
  • MySQL Workbench (MySQL) e/ou pgAdmin (PostgreSQL), conforme o que sua escola usa.

ObjetivoEntender o esqueleto de qualquer página HTML e as tags de texto, link e imagem.

HTML é a linguagem que diz o que existe na página: um título, um parágrafo, um botão. Cada coisa é uma tag, que normalmente abre e fecha: <p>texto</p>. Tags podem ter atributos, que dão informações extras: <a href="painel.html">.

O esqueleto

Toda página começa igual. No VS Code, digite ! e aperte Tab que ele gera isto pronto:

Tags de texto, link e imagem

  • h1 até h6: títulos, do maior para o menor.
  • a: link. O atributo href diz para onde vai.
  • img: imagem. Não fecha. alt é o texto alternativo (acessibilidade, e a prova costuma olhar isso).
  • br e hr também não fecham.
Caminhos de arquivo. href="css/style.css" procura a pasta css ao lado do HTML. Erro de caminho é a causa número 1 de "meu CSS não funciona".

ObjetivoMontar formulários corretos: é a base da tela de login e da tela de cadastro.

Regras que você precisa saber

  • label for = id do campo. Clicar no texto foca o campo. Esquecer isso é erro comum.
  • type muda o teclado e a validação: email, password (esconde), number, date.
  • required, min, maxlength, minlength: validação automática do navegador.
  • id é como o JavaScript encontra o campo. Tem que ser único na página.
  • button type="submit" envia o formulário. Dentro de um form, todo botão é submit se você não disser outra coisa.

ObjetivoControlar tamanho e espaçamento de qualquer elemento.

Todo elemento é uma caixa com 4 camadas, de dentro para fora: conteúdo → padding (espaço interno) → border → margin (espaço externo).

  • display: block ocupa a linha inteira (div, p, h1). inline fica no meio do texto (a, span, strong) e ignora width/height.
  • margin: 10px 20px = 10 em cima/embaixo, 20 nos lados. Com 4 valores: cima, direita, baixo, esquerda (sentido do relógio).
  • Comece todo CSS com * { box-sizing: border-box; }. Evita contas erradas de largura.

ObjetivoEntender como os dados se organizam antes de escrever SQL.

  • Banco de dados: o conjunto (ex.: estoque).
  • Tabela: um assunto (usuario, categoria, produto). Coluna = campo; linha = registro.
  • Chave primária (PK): identifica cada linha, não repete, não fica vazia. Normalmente id.
  • Chave estrangeira (FK): coluna que aponta para a PK de outra tabela. É ela que cria o relacionamento.

DER do projeto

Uma categoria tem vários produtos; cada produto tem uma categoria. Isso é um relacionamento 1 para N (1:N). A FK fica sempre do lado N.

ObjetivoEscrever o script que cria o banco (DDL: CREATE, ALTER, DROP).

Restrições (constraints)

  • PRIMARY KEY: identifica a linha.
  • NOT NULL: campo obrigatório.
  • UNIQUE: não deixa repetir (ótimo para e-mail e CPF).
  • DEFAULT: valor usado quando o INSERT não informa.
  • FOREIGN KEY ... REFERENCES: só aceita um valor que exista na outra tabela.
Ordem importa. Crie primeiro a tabela que é referenciada (turma) e depois a que tem a FK (aluno). Para apagar, o contrário.

Alterar e apagar estrutura

ObjetivoInserir, consultar, alterar e excluir dados (DML). Isto é igual no MySQL e no PostgreSQL.

INSERT: Create

SELECT: Read

UPDATE e DELETE

UPDATE e DELETE sem WHERE alteram a tabela inteira. Escreva o WHERE primeiro, sempre. (O MySQL Workbench até bloqueia isso por padrão, com o "safe update mode".)

Excluir uma turma que ainda tem alunos dá erro de FK. Apague (ou mude) os alunos primeiro.

ObjetivoJuntar tabelas e gerar resumos (contagem, soma, média).

JOIN

O ON liga a FK com a PK. As letras a e t são apelidos das tabelas para escrever menos.

Agregação

Ordem de escrita de um SELECT completo: SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT.

O enunciado (modelo de prova)

Uma loja de materiais de construção precisa controlar seu estoque. O sistema deve ter: login de usuário; uma tela principal que lista os produtos com nome, categoria, quantidade e preço, com busca por nome e destaque para produtos abaixo do estoque mínimo; e uma tela para cadastrar e editar produtos, validando os campos obrigatórios. Entregue também o script do banco de dados.

As 3 telas

1 · Loginindex.html
  • Valida campos vazios
  • Mensagem de login inválido
  • Vai para o painel
2 · Painelpainel.html
  • Tabela de produtos
  • Busca e resumo
  • Editar, excluir, sair
3 · Cadastroproduto.html
  • Inclui e edita
  • Valida cada campo
  • Mensagem de sucesso

Estrutura de pastas

Ordem de trabalho na prova

  1. Leia o enunciado inteiro e sublinhe tabelas, campos e regras (10 min).
  2. Banco primeiro: DER no papel, script SQL, rode e teste com SELECT (30 a 40 min).
  3. HTML das 3 telas, sem estilo, só a estrutura (30 min).
  4. JavaScript: login, listagem, cadastro (1h). É onde vale mais ponto: funcionar.
  5. CSS por último (30 min). Tela feia que funciona vale mais que tela bonita quebrada.
  6. Teste tudo com o checklist da última aula (15 min).
